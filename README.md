# SOOOL WINE FE

와인 탐색, 상세 정보 확인, 메모/위시리스트 저장, 주변 판매처 탐색까지 한 흐름으로 연결한 와인 서비스 프론트엔드 프로젝트입니다.  
단순히 화면을 구현하는 데서 끝나지 않고, 인증 상태 관리, URL 기반 검색/필터 유지, 무한 조회, 지도 연동처럼 실제 서비스에서 자주 마주치는 문제를 프론트엔드 레이어에서 어떻게 풀었는지 보여주는 데 초점을 맞췄습니다.

## 1. Project Summary

### 한 줄 소개
사용자가 와인을 발견하고, 비교하고, 기록하고, 실제 구매 가능한 장소까지 이어서 탐색할 수 있도록 만든 React 기반 와인 서비스 프론트엔드입니다.

### 이 프로젝트에서 보여주고 싶은 것
- 기능 중심이 아니라 사용자 흐름 중심으로 화면을 설계한 경험
- 서버 상태와 클라이언트 상태를 분리해 관리한 경험
- 로그인/토큰 갱신/리다이렉트까지 포함한 인증 UX 설계 경험
- 검색/필터 상태를 URL에 반영해 새로고침과 공유에 강한 UI를 만든 경험
- 외부 지도 SDK를 서비스 UI 안에 자연스럽게 통합한 경험

## 2. Core Features

### 메인 페이지
- 와인 검색 진입점 제공
- 와인 타입별 오늘의 추천 와인 노출
- 주요 와인 생산 지역을 카드 기반으로 탐색

### 와인 창고
- 검색어와 필터를 조합해 와인 목록 탐색
- 커서 기반 무한 조회 패턴으로 추가 데이터 로딩
- 결과가 없을 때 빈 상태 UI 제공

### 와인 상세
- 와인 기본 정보, 국가/도시, 구조감 정보 확인
- 위시리스트 토글
- 사용자 메모 작성, 수정, 삭제
- 관련 와인 추천 영역 제공

### 인증
- 로그인, 회원가입, 아이디 찾기, 비밀번호 재설정 플로우 제공
- 새로고침 이후에도 세션 기준으로 인증 상태 복원
- 비로그인 사용자의 보호 페이지 접근 제어 및 로그인 페이지 리다이렉트

### 마이페이지
- 계정 정보 변경
- 위시리스트 모아보기
- 내가 작성한 메모 관리

### 주변 판매처 탐색
- 현재 위치를 기준으로 카카오맵에서 와인 판매처 검색
- 지도 이동 후 현재 중심 좌표 기준 재검색
- 지도 마커와 리스트 UI를 연결해 탐색성 강화

## 4. Architecture

### Feature-based structure
도메인 단위로 `Main`, `Storage`, `Detail`, `Place`, `Auth`, `My`를 분리해 페이지와 기능이 커져도 변경 범위를 좁게 유지할 수 있도록 구성했습니다.

```text
src
├── apis
├── components
├── features
│   ├── domains
│   │   └── Wine
│   └── shared
│       └── Auth
├── hooks
├── models
├── pages
├── routes
└── stores
```

### Server state / Client state 분리
- 서버에서 가져오는 데이터는 React Query로 관리
- 로그인 사용자 정보와 인증 초기화 같은 전역 UI 상태는 Zustand로 관리
- 관심사의 경계를 분리해 비동기 데이터와 앱 상태가 서로 얽히지 않도록 구성

### API 계층 분리
- Axios 인스턴스를 공통화해 도메인별 API 호출 로직을 모듈화
- 인증이 필요한 요청은 별도 인스턴스로 분리
- 응답 인터셉터에서 토큰 재발급과 재요청 흐름을 통합 처리

## 5. Implementation Highlights

### 1. 토큰 재발급 중복 요청 방지
인증이 필요한 요청에서 `401`이 발생했을 때 모든 요청이 동시에 refresh를 때리지 않도록 queue 형태로 대기시킨 뒤, 새 토큰 발급 후 순차적으로 재실행되도록 구성했습니다.  
실서비스에서 자주 생기는 "만료 순간의 동시 요청 폭주"를 프론트엔드에서 방어한 부분입니다.

### 2. URL 기반 검색/필터 상태 관리
와인 창고의 검색어와 필터를 URL query string에 반영해 다음을 만족하도록 설계했습니다.
- 새로고침 후에도 상태 유지
- 링크 공유 시 동일한 결과 재현
- 허용된 필터만 통과시키는 sanitize 로직으로 잘못된 query 방어

### 3. 재사용 가능한 무한 조회 훅
커서 기반 응답 형식에 맞춰 `useInfiniteScroll` 훅을 공통화했습니다.
- `queryKey`
- `fetchFn`
- `queryParams`

이 세 가지만 바꿔 다양한 목록형 화면에 같은 패턴을 재사용할 수 있도록 만들었습니다.

### 4. 위시리스트 즉시 반응 UX
상세 페이지의 위시리스트 토글은 클라이언트 상태를 먼저 반영하고, 서버 요청은 debounce 처리했습니다.  
사용자는 즉각적인 반응을 느끼고, 서버에는 불필요한 연속 요청이 줄어드는 구조입니다.

### 5. 인증 초기화와 보호 페이지 처리
앱 시작 시 `AuthInitializer`에서 세션 저장소의 토큰을 기준으로 사용자 정보를 복원합니다.  
이 구조 덕분에 새로고침 후에도 로그인 상태를 자연스럽게 유지하고, 보호 페이지에서는 로그인 여부에 따라 진입을 제어할 수 있습니다.

### 6. 지도 UX와 리스트 UX 결합
주변 판매처 페이지는 단순히 지도를 띄우는 수준이 아니라 다음 UX를 함께 제공합니다.
- 현재 위치 기준 초기 검색
- 지도를 움직였을 때 재검색 버튼 노출
- 마커 hover / click과 리스트 hover / click 동기화
- 외부 장소 상세 링크 연결
